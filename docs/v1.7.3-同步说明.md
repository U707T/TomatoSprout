# 番茄芽 v1.7.3 同步说明

这一版只修同步 / 备份，不改交互。

## 1. 合并顺序：规则保护名单必须在插入远端任务之前计算

旧逻辑：

```
1. 遍历远端任务
   - 本地没有 → 插入远端任务
2. localAfter = 重新读取本地任务
3. protectedIds = localAfter 中 updatedAt > lastSync 的任务
4. 只给「不在 protectedIds」的任务应用远端习惯 / 目标规则
```

远端新建的任务 `updatedAt` 本来就晚于本机上次同步时间，插入后必然进入
`protectedIds`，于是它的规则被跳过——任务到了，但排期、连续天数、目标进度全没有。

修复：

```
1. protectedIds = 合并前本地任务中 updatedAt > (lastSync - 5min) 的 id
2. 遍历远端任务并合并
3. 给所有 validTaskIds 中不在 protectedIds 的任务应用规则
```

新任务不在合并前集合里，天然不会被保护；本地确实改过的任务仍然不会被远端规则覆盖。

纯函数在 `sync/MergePolicy.kt`，单测 `MergePolicyTest` 覆盖首次同步、时钟容差、保护名单。

## 2. 同步串行化

`SyncEngine.sync()` 可能同时被手动同步与 `SyncRetryWorker` 调用。
并发会重复合并、重复生成冲突副本，并让 `sync_manifest` 与 `lastSyncedAt` 交错写入。

现在：

```kotlin
suspend fun sync(): SyncResult = syncMutex.withLock { syncLocked() }
```

第二次调用会等第一次结束，然后基于新的 `lastSyncedAt` 判断，通常直接无操作。

## 3. 导入校验与补全

校验新增：

| 字段 | 规则 |
|---|---|
| `goalRules.startDate / endDate` | 必须是 `yyyy-MM-dd` |
| `reminders.timeOfDay` | 必须是 `HH:mm` |
| `checkIns.count` | 不能为负 |
| `habitRules.targetCountPerPeriod` | 不能为负 |
| `goalRules.targetTotalCount / targetTotalSeconds` | 不能为负 |

导入补全：

- 新任务：规则、子任务、提醒、打卡、专注全部导入（与旧版一致）；
- 与本地完全一致的任务：只补「本地缺失」的习惯 / 目标规则与子任务，不覆盖已有规则；
- 冲突任务：保留本地，只提示冲突数。

`SettingsViewModel` 对 `importJson` 与 `resetAll` 都加了兜底，异常会变成消息而不是静默失败。

## 4. 已知边界（未在本版改动）

- 打卡 / 专注仍然「按 id 只增不删」：另一台设备修改了同一条打卡的 `count` 或备注，
  本地不会更新；这一条需要给 `check_ins` / `focus_sessions` 加 `updatedAt` 与逻辑版本，
  属于下一次 schema 变更。
- 子任务没有 `updatedAt`：同名 id 的标题 / 完成状态以先写入的一方为准。
- 冲突判定仍以 `updatedAt` 为主，5 分钟容差只能覆盖常见时钟偏差，不能替代逻辑版本。
