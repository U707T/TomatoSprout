# v1.11.0 — 澎湃 OS 4 焦点通知 / 超级岛适配

v1.10.1 把「探测当闸门」的问题修掉之后，仍有用户反馈澎湃 OS 4 上不出岛。这次把**协议本身**按三处硬证据
重写了一遍，并补上了岛内交互的基础功能。

---

## 一、结论先行

| 问题 | 结论 |
|---|---|
| 澎湃 OS 4 换了协议？ | **没有**。`miui.focus.param` 仍是 `param_v2` 单层结构，官方文档（pId=2131，2026-01-29 更新）与 OS3 一致 |
| 那为什么不出岛？ | 两道**应用无法自己完成**的闸门：① 系统里本应用的「焦点通知」开关；② 澎湃 OS 4 起的**云端白名单**（开平开通超级岛服务 + 证书指纹 + 场景审核）。未收录的第三方应用，参数再对也不会出岛 |
| 参数写错会怎样？ | 系统只忽略对不上的块，不会崩；最差退化成一条普通通知（`filterWhenNoPermission=false` 保证不被整帧过滤） |
| 能做什么？ | 把载荷对齐**系统自己**的倒计时/录音机焦点通知；把判定收敛成「小米机型就发」；把诊断摊开，让用户一眼看出卡在哪道闸门 |

> 一句话：**载荷要对，闸门在系统侧。** App 的正确做法是把参数写对、把话说清楚，而不是拿探测结果当开关。

## 二、证据来源

| 编号 | 来源 | 用途 |
|---|---|---|
| A | 小米澎湃 OS 开发者平台《开发指南》pId=2131（2026-01-29）、《常见 Q&A》pId=2146（2025-10-23） | 字段名、单位、默认值、`timeout` / `islandTimeout` / `cancel` / `dismissIsland` 语义 |
| B | 系统时钟「倒计时」与录音机「正计时」的 `miui.focus.param` 实机 dump | `scene`、`highlightInfo`、`animTextInfo`、`param_island` 的真实取值 |
| C | 反向阅读 `miui.systemui.dynamicisland` 插件（模板选择顺序、`compareState` 排序） | `islandPriority` 的方向、`expandedTime` 的作用、`smallIslandArea` 必须包一层 `picInfo` |

是死代码），本版已删除。


### 3.1 计时参数

| 状态 | `timerType` | `timerWhen` | `timerTotal` | 说明 |
|---|---|---|---|---|
| 倒计时运行 | `-1` | 结束时刻 | 计划毫秒 | 系统自己走秒 |
| 倒计时暂停 | `-2` | 结束时刻 | 计划毫秒 | 按 `timerSystemCurrent` 冻结读数 |
| 正计时运行 | `1` | 开始时刻 | `0` | 与系统录音机一致 |
| 正计时暂停 | `2` | 开始时刻 | `0` | 同上 |
| 已完成 | 不给 `timerInfo` | — | — | 卡片与岛都显示 `00:00`，不留一个永远不动的计时器 |

### 3.2 与 v1.10.x 的差异

| 位置 | v1.10.x | v1.11.0 | 原因 |
|---|---|---|---|
| `islandProperty` | `2` | `1` | 官方语义：1 信息展示、2 操作为主；倒计时以信息为主 |
| `islandPriority` | 未给（等价 1） | 显式 `1` | 反向实现里「数值小的先占大岛」，`2` 还会限制点击展开 |
| `expandedTime` | 未给 | `60` | 与系统时钟倒计时一致，避免岛一直摊开 |
| 通知卡片计时 | 只在岛上 `sameWidthDigitInfo` | `baseInfo` 里也给一份 | 模板选择器读的是「首个区域模块」的 `timerInfo` |
| 完成提示 | 不给 `dismissIsland` | `dismissIsland = true` | 一次性提示不留在岛上 |
| 品牌色 | 调用方传 `accentColor` | 载荷内部按状态推导 | 少一个可能传错的参数（休息绿 / 完成深绿） |

## 四、判定策略（`LiveSurfacePolicy`）

```
实时活动开关关闭 → 普通卡片
强制焦点通知     → 带 miui.focus.* extras（任何机型）
小米/Redmi/POCO  → 带 miui.focus.* extras
其余：SDK ≥ 36 且允许提升通知 → Android 16 实时更新
其余：→ 普通卡片
```

**不再用 `notification_focus_protocol` / `canShowFocus` 决定发不发。** 这两个值只进自检面板：
澎湃 OS 4 上协议键可能整个缺失（读成 0 就被当成「不支持」），`canShowFocus` 又会因云端白名单返回 false。
把它们当闸门，等于把上岛的路整条关掉 —— 这正是 v1.10.0 的 bug。

## 五、本版补齐的基础功能

| 功能 | 实现 |
|---|---|
| 岛内暂停 / 继续 / 结束 | `miui.focus.actions` + 广播 PendingIntent（`FLAG_RECEIVER_FOREGROUND`），点了不跳 App |
| **新增：延长 5 分钟** | 通知栏动作 + `TimerEngine.extend()`；正计时、已结束、已暂停不生效，上限 3 小时 |
| 专注完成 / 休息结束提示 | 独立通知 id（1004），岛驻留 20 秒后自动消失，不覆盖进行中的专注 |
| 测试岛 | 独立 id（1003），60 秒后自动撤掉，不打断真实专注；发送失败会明说「系统拒绝了这条通知」 |
| 进度环 | 小岛 `combinePicInfo.progressInfo`，按已专注百分比；正计时只放图标 |
| 息屏文案 | `aodTitle` 只给分钟，避免两次刷新之间跳秒 |
| 自检 | 机型 / 协议 / 焦点开关 / SQLite 无关的 `SDK_INT_FULL` / 提升通知 / **本次档位与判定原因** / 最近一次发送 / 针对当前状态的提示 |

## 六、自检与排查

「我的 → 提醒 → 系统实时活动」：

1. **本次走**：显示当前会走哪一档；原因里会写明是「小米机型」「强制」「实时活动已关闭」还是「只支持普通卡片」。
2. **焦点通知开关**：
   - `已允许` —— 参数问题，点「发送测试岛」看是否出岛；
   - `已关闭` —— 去系统里打开（点「系统设置」直接跳）；
   - `系统未提供接口` —— 澎湃 OS 4 的常见形态，只能靠云端白名单。
3. **提示**：会根据上面的组合给出下一步（白名单未收录 / 需要系统模块解锁 / 强制已开启）。

真机排查命令：

```bash
adb shell settings get system notification_focus_protocol   # 空 = OS4 常见形态
adb shell dumpsys notification --noredact | grep -A3 miui.focus   # 看 extras 是否带上
adb shell dumpsys notification | grep -i "FLAG_PROMOTED"           # Android 16 提升是否生效
# 系统侧日志（官方流程）：复现后 *#*#284#*#*，2–3 分钟后 sdcard/MIUI/debug_log 取 zip
```

## 七、验证

```bash
./gradlew :core:domain:test :app:testDebugUnitTest   # domain 54 + app 21
./gradlew :app:lintDebug                             # 0 error
./gradlew :app:assembleDebug                         # 通过
```

单测锁的语义：

- `param_v2` 单层、`sequence` 透传、`filterWhenNoPermission = false`；
- 倒计时给绝对结束时刻，暂停用 `-2 / 2` 冻结，已完成不给 `timerInfo`；
- `islandProperty = 1`、`islandPriority = 1`、`expandedTime = 60`、完成帧 `dismissIsland = true`；
- 小岛只放 `picInfo` 或 `combinePicInfo`，进度夹在 0..100；
- 载荷 < 3 KB；
- `TimerEngine.extend`：只对进行中的倒计时生效、上限 3 小时、不改已流逝时长。

## 八、已知限制

- **云端白名单**：澎湃 OS 4 是否放出岛由小米侧决定，第三方应用只能把参数写对；未收录时通知、计时、结算全部正常，只是不上岛。
- **模板是私有协议**：字段随 ROM 演进（OS2 `param_v2` → OS3 `param_island` → OS4 白名单），这里只写官方文档与系统 App dump 里出现过的字段，缺字段最多是「某个块不显示」。
- **无前台服务**：进程被杀后岛与通知的秒数继续走（系统时钟），但结算要等回到 App。
- 岛内按钮是否可点取决于 ROM；通知本身的标准按钮在所有系统上都在。
