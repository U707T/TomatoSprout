# v1.10.0 — Android 16 与澎湃 OS 超级岛适配

本次改动解决两件事：

1. **targetSdk 35 → 36**：把 Android 16 的行为变更逐条过一遍，不留「靠兼容模式跑」的尾巴。
2. **专注计时进系统实时活动**：澎湃 OS 的**超级岛 / 焦点通知**与 Android 16 的**进度型通知（Live Updates）**都能显示番茄倒计时，秒数由系统自己走。

没有新增任何权限，没有引入前台服务，也没有引入小米 SDK。

---

## 一、三档呈现

同一个「进行中的专注」，按机型能力挑一条渲染，**互斥、不叠加**：

| 档位 | 判定 | 呈现 | 代码 |
|---|---|---|---|
| 超级岛 / 焦点通知 | 澎湃 OS，`notification_focus_protocol ≥ 2` 且焦点通知未被关 | 状态栏小岛 + 展开大岛（番茄图标 + 大号倒计时 + 进度环）、息屏 AOD 文案、通知里的暂停 / 结束 | `FocusLiveNotification` → `Surface.HYPER_OS` |
| Android 16 实时更新 | 非小米，`SDK_INT ≥ 36` 且用户允许提升通知 | `Notification.ProgressStyle` 进度条 + 状态栏胶囊倒计时，可提升为常驻 | 同上 → `Surface.LIVE_UPDATE` |
| 普通卡片 | 其余情况（含小米但焦点通知被关、用户关掉实时活动） | 原来的自绘 RemoteViews 卡片 | 同上 → `Surface.PLAIN` |

判定集中在 `FocusLiveNotification.chooseSurface()`；能力探测结果缓存 60 秒，避免每 10 秒调一次系统 Provider。

## 二、澎湃 OS 超级岛

### 2.1 探测（不申请权限、不反射系统属性）

| 入口 | 用法 | 读取方式 |
|---|---|---|
| `Settings.System["notification_focus_protocol"]` | 0 = 不支持；2 = 焦点通知（OS2）；3+ = 超级岛（OS3 / OS4） | `Settings.System.getInt`，读不到给 0 |
| `content://miui.statusbar.notification.public` 的 `canShowFocus` 调用 | 本 App 的「焦点通知」开关 | `ContentResolver.call`，返回 `null` 表示系统没提供该接口 |

- 只有**明确 false** 才算「不让用」；`null`（查不到）仍然尝试发焦点通知 —— 多试一次没有代价，失败了系统会当成普通通知。
- 全部包在 `runCatching` 里，任何 ROM 差异最多退化成普通卡片。

### 2.2 extras 结构

```kotlin
notification.extras["miui.focus.param"]   = <payload JSON 字符串>
notification.extras["miui.focus.pics"]    = Bundle   // key → Icon，JSON 里的 pic 字符串引用
notification.extras["miui.focus.actions"] = Bundle   // key → Notification.Action
```

### 2.3 payload 字段（`FocusIslandPayload`）

| 位置 | 字段 | 本项目取值 | 说明 |
|---|---|---|---|
| 顶层 | `protocol` / `scene` | `1` / `timer` | 模板分派 |
| 顶层 | `ticker` / `content` | `专注中 · 写周报` / `专注中` | OS2 状态栏焦点文字；正文只放状态，任务名超 16 字截断 |
| 顶层 | `timerType` / `timerWhen` / `timerSystemCurrent` / `timerTotal` | `-1` / 结束时刻 / 当前时刻 / 计划毫秒 | 倒计时＝结束时间 + 当前时间，由 SystemUI 走秒 |
| `param_v2` | `aodTitle` / `aodPic` | `专注中 · 写周报` / 番茄图标 | 息屏显示。**不写秒数**：两次刷新之间会变成过期文本，秒数交给 `timerInfo` |
| `param_v2` | `highlightInfo.timerInfo` | 同上 | 焦点通知展开区的大号数字 |
| `param_v2` | `hintInfo` | `专注中` + `25 分钟` | 补充说明行 |
| `param_v2` | `actions[]` | `miui.focus.action_toggle` / `_stop` | 键名与 actions Bundle 对应 |
| `param_v2` | `param_island.bigIslandArea.imageTextInfoLeft` | 番茄图标 | 展开大岛左侧 |
| `param_v2` | `param_island.bigIslandArea.sameWidthDigitInfo.timerInfo` | 同上 | 展开大岛等宽数字 |
| `param_v2` | `param_island.smallIslandArea.combinePicInfo` | 番茄图标 + 进度环 | 收起小岛 |
| `param_v2` | `islandProperty` / `islandOrder` / `expandedTime` | `1` / `true` / `60` | 信息展示型岛；进场 60 秒后自动收起 |

`timerType` 语义：`-1` = 倒计时（`timerWhen` 是结束时刻，`timerTotal` 是总时长）；`0` = 正计时（`timerWhen` 是开始时刻）。暂停时**不下发任何 timerInfo** —— 宁可只显示「已暂停」两个字，也不让岛上的秒数在暂停后继续跳。

体积与耗电：模板给了绝对时间，系统自己走秒，App **不需要**每秒重发通知。`FocusLiveController` 对实时活动档位做了 10 秒内容指纹 + 60 秒同内容兜底重发，比 v1.9 的「每秒 notify 一次」少 60～90% 的跨进程调用。

## 三、Android 16 实时更新

- 样式：`Notification.ProgressStyle` + 单个长度 100 的分段（`setProgress` 的上限就是分段长度之和），`setProgress(已用百分比)`。
- 走秒：`setWhen(结束时刻) + setUsesChronometer(true) + setChronometerCountDown(true)`。状态栏胶囊与锁屏都显示系统计时器，**进程被回收后数字照走**。
- 暂停：`setUsesChronometer(false)` + `setShortCriticalText("已暂停")`（胶囊文案）。
- 提升为常驻实时活动：
  - `NotificationManager.canPostPromotedNotifications()` 判断用户是否允许；
  - `setRequestPromotedOngoing(true)` 是 **Android 16 QPR1（`SDK_INT_FULL ≥ 3600001`）** 才有的接口，用 `Build.VERSION.SDK_INT_FULL` 判断，低版本不调用；
  - 用户没允许时**不降级成半吊子的系统通知**，直接用自绘卡片，和 App 内视觉一致。
- 引导：设置页「提醒 → 系统实时活动」会显示当前状态，未开启时点一行跳到 `Settings.ACTION_APP_NOTIFICATION_PROMOTION_SETTINGS`。

## 四、targetSdk 36 行为变更逐项核对

| Android 16 变更 | 对本项目的影响 | 结论 / 位置 |
|---|---|---|
| Edge-to-edge 不可再 opt-out | 早已 `enableEdgeToEdge()` + 各页 `statusBarsPadding/navigationBarsPadding/displayCutoutPadding`，未使用 `windowOptOutEdgeToEdgeEnforcement` | 无需改动 |
| 预测式返回默认开启，`onBackPressed` 不再回调 | 全项目没有 `onBackPressed` / `onKeyDown(KEYCODE_BACK)` 覆写，返回全部走 Compose Navigation | Manifest 显式 `android:enableOnBackInvokedCallback="true"`，行为显式化 |
| sw≥600dp 忽略方向 / 可调整大小 / 宽高比限制 | 没有 `screenOrientation`、没有 `setRequestedOrientation`，列表与卡片用自适应约束 | 无需改动（**注意**：targetSdk 37 起连兼容模式都没有） |
| 固定频率任务补偿只执行一次 | 只有一个 `OneTimeWorkRequest`（WebDAV 失败重试），不用 `scheduleAtFixedRate` | 不受影响 |
| JobScheduler 配额按待机分组收紧 | 同上，单次任务 | 不受影响 |
| 16 KB page size | arm64 的 `libandroidx.graphics.path.so` / `libdatastore_shared_counter.so` 的 LOAD 段 `p_align = 0x4000`（已核对 APK），无自研 so | 已兼容，无需 `android:pageSizeCompat` |
| MediaStore `getVersion()` 按应用隔离 | 未使用 | 无影响 |
| Safer Intents（需 opt-in） | 未声明 `android:intentMatchingFlags` | 无影响 |
| 健康权限 / 蓝牙绑定 | 未使用相关 API | 无影响 |
| 自动主题图标（16 QPR2） | `mipmap-anydpi-v26` 已有 `<monochrome>` 图层 | 已适配 |
| 无障碍 announce 废弃 | 未使用 `announceForAccessibility` | 无影响 |

### Android 17（API 37）前瞻

机身若已是澎湃 OS 4 / Android 17，本版本 targetSdk 36 只受「所有应用」级变更影响，已核对：

- **后台音频硬化**：白噪音等只在专注页前台播放，不做后台播放，暂不受影响；将来若 targetSdk 37，需要按「前台服务 + 使用时权限」重新评估音频路径。
- **应用内存上限**：命中时 `ApplicationExitInfo` 的 `REASON_OTHER` 描述里会带 `MemoryLimiter:AnonSwap`，排查时先用它确认。
- **隐式 URI 授权收紧（Android 18 生效）**：分享海报已显式 `FLAG_GRANT_READ_URI_PERMISSION`。

## 五、设置与开关

「我的 → 提醒」新增两行：

- **实时活动 / 超级岛**：默认开启；关闭后专注时只发普通卡片（不写库、不参与 WebDAV 同步与 JSON 备份，属于本机显示偏好，和触感 / 音效一个层级）。
- **系统实时活动**：只读状态 + 需要时跳系统设置。四档文案：
  - `澎湃 OS 超级岛 · 已允许`
  - `澎湃 OS 焦点通知未允许，点这里去开启`
  - `Android 实时更新 · 已允许` / `…未允许，点这里去开启`
  - `当前系统只显示普通通知卡片`

开关存在 `live_activity`（DataStore），默认 `true`；旧的备份文件没有这个字段时按默认值走，不影响导入。

## 六、验证

本地已跑：

```bash
./gradlew :app:testDebugUnitTest   # 13 个（新增 8 个超级岛载荷用例）
./gradlew :app:lintDebug           # 0 error
./gradlew :app:assembleDebug       # 通过
```

单测锁的是语义而不是字符串：倒计时必须给绝对结束时间、暂停不许带 timerInfo、进度必须夹在 0..100、正计时不许给 `timerTotal`、ticker 截断与空标题兜底。

真机上请按这四步验（沙箱没有小米真机，界面上的最终样子需要在手机上确认）：

1. 开始一次专注，看状态栏是否出现小岛（番茄图标 + 倒计时）。
2. 展开岛：应有大号数字 + 进度环；点暂停 → 数字停住并显示「已暂停」，点继续恢复。
3. 息屏：AOD 上应显示剩余时间。
4. 系统里关掉「焦点通知」再开始一次：应退回 App 自绘卡片，且设置页那行变成「未允许，点这里去开启」。

排查命令：

```bash
adb shell settings get system notification_focus_protocol          # 0/2/3
adb shell dumpsys notification --noredact | grep -A3 miui.focus    # 看 extras 是否带上
adb shell dumpsys notification | grep -i "promoted\|FLAG_PROMOTED" # Android 16 提升是否生效
```

## 七、已知限制

- 超级岛模板是**厂商私有协议**，字段随 ROM 版本演进（OS2 的 `param_v2` → OS3 加 `param_island` → OS4 加 `islandProperty=0` 的一次性岛语义）。这里只写官方样例里出现过的字段，缺字段最多是「某个块不显示」，不会崩；系统版本再变时先看 `FocusIslandPayload` 与本文档。
- 岛内按钮的可用性取决于 ROM：模板里挂了 `actions`，但部分版本只渲染展示态。**通知本身的暂停 / 结束按钮在所有系统上都可用**，是兜底路径。
- 仍然不申请前台服务：进程被杀后岛与通知的秒数继续走（系统时钟），但「结算」要等回到 App；这是本项目的既有取舍，不是这次改出来的。
- 焦点通知的「允许」开关在澎湃 OS 的通知设置里，不同版本入口位置会变，所以只跳标准 `ACTION_APP_NOTIFICATION_SETTINGS`，不硬编码厂商 Activity。
