# v1.10.x — Android 16 与澎湃 OS 超级岛适配

本次改动解决两件事：

1. **targetSdk 35 → 36**：把 Android 16 的行为变更逐条过一遍，不留「靠兼容模式跑」的尾巴。
2. **专注计时进系统实时活动**：澎湃 OS 的**超级岛 / 焦点通知**与 Android 16 的**进度型通知（Live Updates）**都能显示番茄倒计时，秒数由系统自己走。

没有新增任何权限，没有引入前台服务，也没有引入小米 SDK。

> **v1.10.1 修订**：v1.10.0 的判定写错了 —— 它要求「焦点协议 ≥ 2 **且** 已授权」才发焦点通知 extras，
> 而这个协议值是靠 `Settings.System` 读的，小米部分版本读不到就返回 0，结果直接退到自绘卡片，
> **等于把上岛的路整条关掉**。现在改为：只要是小米 / Redmi / POCO 机型就带 extras，
> 能不能显示完全交给系统决定；载荷也按真机可用的第三方实现重写（见 §2.3）。

---

## 一、三档呈现

同一个「进行中的专注」，按机型能力挑一条渲染，**互斥、不叠加**：

| 档位 | 判定 | 呈现 | 代码 |
|---|---|---|---|
| 超级岛 / 焦点通知 | `Build.MANUFACTURER` 或 `Build.BRAND` ∈ {xiaomi, redmi, poco} | 小岛 + 展开大岛（图标 + 状态 + 大号倒计时）、息屏文案、通知里的暂停 / 结束 | `FocusLiveNotification` → `Surface.HYPER_OS` |
| Android 16 实时更新 | 非小米，`SDK_INT ≥ 36` 且用户允许提升通知 | `Notification.ProgressStyle` 进度条 + 状态栏胶囊倒计时 | 同上 → `Surface.LIVE_UPDATE` |
| 普通卡片 | 其余情况（用户关掉实时活动、非小米旧系统、不许提升通知） | 原来的自绘 RemoteViews 卡片 | 同上 → `Surface.PLAIN` |

**判定只做一件事：是不是小米机。** 不拿「协议版本」「焦点通知开关」当闸门 —— 那两个只写进自检报告，
因为系统读不到时它们会返回 0 / null，而 extras 本身是「多带无害」的：系统不认识就只是当普通通知显示。

## 二、澎湃 OS 超级岛

### 2.1 探测（只用于自检，不控制发送）

| 入口 | 用途 | 读取方式 |
|---|---|---|
| `Settings.System["notification_focus_protocol"]` | 自检显示（0 不支持 / 2 焦点通知 / 3+ 超级岛） | `getInt`，读不到给 0 |
| `content://miui.statusbar.notification.public` 的 `canShowFocus` | 自检显示本应用「焦点通知」开关是否打开 | `ContentResolver.call`，`null` = 系统没提供接口 |
| `Build.MANUFACTURER` / `Build.BRAND` | **唯一**影响发送行为的判定 | 字符串比较，不反射系统属性 |

### 2.2 extras 结构

```kotlin
notification.extras["miui.focus.param"]   = <payload JSON 字符串>
notification.extras["miui.focus.pics"]    = Bundle   // key → Icon，JSON 里的 pic 字符串引用
notification.extras["miui.focus.actions"] = Bundle   // key → Notification.Action
```

### 2.3 payload（`FocusIslandPayload`）

写法对齐多个**已在真机上出岛**的第三方实现，而不是照抄系统 App 的样例：

| 位置 | 字段 | 取值 | 为什么 |
|---|---|---|---|
| `param_v2` | `protocol` / `business` | `1` / `pomodoro` | 模板分派，business 只做透传 |
| `param_v2` | `sequence` | 单调递增 Long | **必带**：系统据此判断哪一帧最新，缺了后续更新会被当旧帧丢掉 |
| `param_v2` | `filterWhenNoPermission` | `false` | **必带**：没有焦点通知授权时不要把整帧过滤掉 |
| `param_v2` | `ticker` / `aodTitle` / `aodPic` | `专注中 · 写周报` / 番茄图标 | 状态栏与息屏文案；**不写秒数**，否则两次刷新之间就是过期文本 |
| `param_v2` | `highlightInfo` | `type=1` + `timerInfo` + `subContent`(任务名) | 焦点通知展开区的大号数字 |
| `param_v2` | `hintInfo` | `专注中` + `25 分钟` | 补充说明行 |
| `param_v2` | `actions[]` | `miui.focus.action_toggle` / `_stop` + 配色 | 键名与 actions Bundle 对应 |
| `param_island` | `islandProperty` | `2` | 交互型岛；`0` 在 OS4 只闪一次 |
| `param_island` | `islandTimeout` | 剩余秒数 + 300，夹在 60..43200 | 计时结束岛自动收起，不挂着 |
| `param_island` | `bigIslandArea.imageTextInfoLeft` | 番茄图标 + `textInfo.title`（状态） | 左侧图标 + 文字 |
| `param_island` | `bigIslandArea.sameWidthDigitInfo` | `timerInfo`；暂停时用 `digit` 静态文字 | 大号等宽数字 |
| `param_island` | `smallIslandArea.picInfo` | 番茄图标 | **只放图标**：`combinePicInfo` 在部分版本会渲染成空白 |

计时参数（`timerInfo`）：

| 状态 | `timerType` | `timerWhen` | `timerTotal` | 备注 |
|---|---|---|---|---|
| 倒计时运行 | `-1` | 结束时刻 | 计划毫秒 | 系统据此自己走秒 |
| 正计时运行 | `1` | 开始时刻 | `0` | 与系统录音机 / 训练计时一致 |
| 暂停 / 非运行 | 不给 `timerInfo` | — | — | 宁可只显示静态文字，也不让秒数继续跳 |

另外两个字段名同时写：`timerSystemCurrent` **和** `timerCurrent` —— 官方字段表与官方样例不一致，
两个都给，系统读哪个都能对上。

体积与耗电：模板给的是绝对时间，系统自己走秒，App **不需要**每秒重发通知。

### 2.5 系统开关（必须由用户在系统里打开）

出岛链条上有一段**应用无法自己完成**：澎湃 OS 需要为本应用打开「焦点通知」。
入口在「设置 → 通知与控制中心 → 番茄芽 → 焦点通知 / 超级岛」（不同 OS 版本措辞与层级会变），
所以 App 只跳标准 `ACTION_APP_NOTIFICATION_SETTINGS`，不硬编码厂商 Activity。

判断是否已打开：`canShowFocus` = true。自检页会直接显示这一项。

## 三、Android 16 实时更新

- 样式：`Notification.ProgressStyle` + 单个长度 100 的分段（`setProgress` 的上限就是分段长度之和），`setProgress(已用百分比)`。
- 走秒：`setWhen(结束时刻) + setUsesChronometer(true) + setChronometerCountDown(true)`，进程被回收后数字照走。
- 暂停：`setUsesChronometer(false)` + `setShortCriticalText("已暂停")`。
- 提升为常驻：`canPostPromotedNotifications()` 判断用户是否允许；`setRequestPromotedOngoing(true)` 是
  **Android 16 QPR1（`SDK_INT_FULL ≥ 3600001`）** 才有的接口，用版本号判断后再调，低版本不碰。
- 不允许提升时**不降级成半吊子系统样式**，直接用自绘卡片。
- 引导：自检页会给出 `ACTION_APP_NOTIFICATION_PROMOTION_SETTINGS` 入口。

## 四、targetSdk 36 行为变更逐项核对

| Android 16 变更 | 对本项目的影响 | 结论 / 位置 |
|---|---|---|
| Edge-to-edge 不可再 opt-out | 早已 `enableEdgeToEdge()` + 各页 Insets，未使用 `windowOptOutEdgeToEdgeEnforcement` | 无需改动 |
| 预测式返回默认开启，`onBackPressed` 不再回调 | 全项目无 `onBackPressed` 覆写，返回全走 Compose Navigation | Manifest 显式 `android:enableOnBackInvokedCallback="true"` |
| sw≥600dp 忽略方向 / 尺寸限制 | 没有 `screenOrientation`、没有 `setRequestedOrientation` | 无需改动（targetSdk 37 起连兼容模式都没有） |
| 固定频率任务补偿只执行一次 | 只有一个 `OneTimeWorkRequest`（WebDAV 重试） | 不受影响 |
| JobScheduler 配额收紧 | 同上，单次任务 | 不受影响 |
| 16 KB page size | APK 内 arm64 so 的 LOAD 段 `p_align = 0x4000` | 已兼容 |
| MediaStore `getVersion()` 按应用隔离 | 未使用 | 无影响 |
| Safer Intents（opt-in） | 未声明 `android:intentMatchingFlags` | 无影响 |
| 自动主题图标（16 QPR2） | `mipmap-anydpi-v26` 已有 `<monochrome>` | 已适配 |
| 无障碍 announce 废弃 | 未使用 | 无影响 |

### Android 17（API 37）前瞻

- **后台音频硬化**：白噪音只在专注页前台播放，不做后台播放；将来 targetSdk 37 需重新评估。
- **应用内存上限**：命中时 `ApplicationExitInfo` 的 `REASON_OTHER` 描述含 `MemoryLimiter:AnonSwap`。
- **隐式 URI 授权收紧（Android 18）**：分享海报已显式 `FLAG_GRANT_READ_URI_PERMISSION`。

## 五、设置与自检

「我的 → 提醒」两行：

- **实时活动 / 超级岛**：默认开启；关闭后只发普通卡片。本机偏好，不参与 WebDAV 同步与 JSON 备份。
- **系统实时活动**：一行状态，点开是**实时活动自检**：
  - 小米机型 / 品牌；
  - 焦点协议版本、焦点通知开关（已允许 / 已关闭 / 系统未提供接口）；
  - Android 版本、`SDK_INT_FULL`、是否允许提升通知、通知权限；
  - 本次会走哪一档；
  - **最近一次发送**（时间 · 档位 · 内容指纹）；
  - 按钮：`发送测试岛`（120 秒假专注，60 秒后自动消失）、`系统设置`。

出问题时的定位顺序：先点「发送测试岛」→ 没反应就看「焦点通知开关」→ 是「已关闭」就去系统里打开；
是「系统未提供接口」则说明该 ROM 没暴露开关，只能等系统侧放开。

## 六、验证

本地已跑：

```bash
./gradlew :app:testDebugUnitTest   # 14 个（9 个超级岛载荷用例）
./gradlew :app:lintDebug           # 0 error
./gradlew :app:assembleDebug       # 通过
```

单测锁的是语义而不是字符串：倒计时必须给绝对结束时间、暂停不许带 timerInfo、进度夹在 0..100、
正计时 `timerType=1` 且 `timerTotal=0`、`islandProperty=2`、`filterWhenNoPermission=false`、
`sequence` 透传、小岛只放 `picInfo`、ticker 截断与空标题兜底。

真机验证：

1. 「我的 → 提醒 → 系统实时活动 → 发送测试岛」：状态栏应出现番茄小岛。
2. 展开岛：图标 + 状态 + 大号倒计时；点暂停 → 数字停住，点继续恢复。
3. 息屏：AOD 显示「专注中 · 任务名」。
4. 系统里关掉焦点通知再发测试：自检页应显示「已关闭」，岛不出来但通知仍在。

排查命令：

```bash

adb shell dumpsys notification --noredact | grep -A3 miui.focus
adb shell dumpsys notification | grep -i "FLAG_PROMOTED"   # Android 16 提升是否生效
```

## 七、已知限制

- 超级岛模板是**厂商私有协议**，字段随 ROM 版本演进（OS2 的 `param_v2` → OS3 加 `param_island` → OS4 加 `islandProperty=0` 语义）。
  这里只写官方样例与真机可用实现里出现过的字段，缺字段最多是「某个块不显示」，不会崩。
- **系统侧的「焦点通知」开关必须用户自己打开**，应用无法代劳（那是系统签名级设置）。没打开时岛不会出现，
  但通知、计时、结算全部正常。
- 岛内按钮是否可点取决于 ROM；通知本身的标准按钮（暂停 / 结束）在所有系统上都在。
- 仍然不申请前台服务：进程被杀后岛与通知的秒数继续走（系统时钟），但结算要等回到 App。
