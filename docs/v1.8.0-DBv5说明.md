# 番茄芽 v1.8.0 · DB v5 说明

这一版同时补上番茄ToDo 的最后两个公开链路能力（打断原因、长休息），
并把打卡 / 专注从「只增不删」升级为记录级双向合并。

## 1. 迁移 4 → 5

```sql
ALTER TABLE check_ins ADD COLUMN updatedAt INTEGER NOT NULL DEFAULT 0;
UPDATE check_ins SET updatedAt = createdAt WHERE updatedAt = 0;

ALTER TABLE focus_sessions ADD COLUMN updatedAt INTEGER NOT NULL DEFAULT 0;
UPDATE focus_sessions SET updatedAt = endedAt WHERE updatedAt = 0;

ALTER TABLE focus_sessions ADD COLUMN interruptReason TEXT;
```

- Entity 上对应 `@ColumnInfo(defaultValue = "0")`，与迁移后的表结构一致；
- 迁移后用 SQLite 逐列比对 `PRAGMA table_info` 与 `schemas/5.json`：
  `check_ins` / `focus_sessions` 的字段类型、NOT NULL、默认值全部一致；
- 没有 DROP TABLE，没有重建索引。

## 2. 记录级双向合并

### 2.1 打卡

`check_ins` 的唯一键是 `(taskId, checkDate, isMakeup)`，不是 id。
两台设备各自新建同一天的打卡会得到两个不同 UUID，直接 upsert 会撞唯一索引，
让整次同步失败。`CheckInRepositoryImpl.mergeAll` 因此按两层匹配：

| 情况 | 处理 |
|---|---|
| 同 id 本地已存在 | `updatedAt` 较新者覆盖；两端都未删除时 `count = max(local, remote)` |
| 不同 id、同唯一键 | 保留本地 id，合并较新的元数据，`count = max` |
| 都没有 | 插入 |
| 远端更旧但 count 更大 | 保留本地备注 / 心情，只把 count 抬高 |

`count` 取 `max` 而不是相加：两台设备都从 1 加到 2 时，max 仍然是 2（目标次数语义），
不会出现「2/1」这种越界显示；代价是极端情况下少算一次，但不会破坏达标判断。

删除 / 复活按 `updatedAt` 较新者生效，旧快照不会把已撤销的打卡拉回来。

### 2.2 专注

`focus_sessions` 只有 id 主键，直接按 `updatedAt` 较新者覆盖：
备注、删除、`interruptReason`、`outcome` 都会随较新记录传播。

### 2.3 时间戳单调

`updateCount` / `updateMeta` / `updateNote` / `softDelete` 的 SQL 使用
`updatedAt = MAX(updatedAt, :at)`。即使一次补卡写入的是过去的 `endedAt`，
也不会把记录的 `updatedAt` 拉回过去，避免合并时被误判成旧数据。

## 3. 同步格式 v3

- `SyncSnapshot.schemaVersion = 3`；
- 新 App 仍可导入 v2 备份（`updatedAt` 默认 0、`interruptReason` 为 null）；
- 旧 App 读到 v3 会提示「版本过新」，需要同步升级——这是有意的：
  旧版不认识 `updatedAt`，继续写回会破坏合并语义。

## 4. 打断原因

- `InterruptReason`：`DISTRACTED / INTERRUPTED / GAVE_UP / OTHER`；
- 仅 `MANUAL_STOP` 且未达计划时长时记录；严格模式仍直接丢弃；
- 停止确认弹窗选择，历史页显示「中断 · 分心了」，统计页按区间 + 任务筛选聚合；
- 旧数据没有原因，统计里归为「未记录」。

## 5. 长休息

- `BreakCycle.isLongBreakDue(count)`：`count > 0 && count % 4 == 0`；
- 统计口径：当天 `mode=pomodoro` 且 `outcome=completed` 的专注数（含自由专注）；
- 第 4 / 8 / 12… 个番茄完成后，结算摘要的主按钮变为「长休息 15 分钟」；
- 时长在设置中可调 10–60 分钟，默认 15；参与同步与备份导入。

## 6. 已知边界

- 打卡 `count` 取 max 而不是求和；这是为了不越过目标次数，代价是两台设备同时
  各 +1 时只算一次。
- 旧版 App 不能读写 v3 快照。
- 子任务仍没有 `updatedAt`，标题 / 完成状态以先写入的一方为准。
