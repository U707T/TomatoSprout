# 番茄芽 v1.8.2 · 数据层收尾

这一版把最后两类「只能新增、不能改」的记录补成双向合并，并把子任务删除做成墓碑。
做完后，任务 / 子任务 / 打卡 / 专注 / 提醒 / 愿望全部具备记录级合并语义。

## 1. 迁移 6 → 7

```sql
ALTER TABLE reminder_rules ADD COLUMN updatedAt INTEGER NOT NULL DEFAULT 0;
UPDATE reminder_rules SET updatedAt = 1 WHERE updatedAt = 0;

ALTER TABLE wish_items ADD COLUMN updatedAt INTEGER NOT NULL DEFAULT 0;
UPDATE wish_items SET updatedAt = createdAt WHERE updatedAt = 0;

ALTER TABLE subtasks ADD COLUMN deletedAt INTEGER;
```

- `reminder_rules` 没有 createdAt，旧行回填 1，视为「本地已存在」；
  远端旧快照的 `updatedAt = 0` 不会覆盖本地提醒。
- `wish_items` 回填 createdAt。
- `subtasks.deletedAt` 可空，旧行全部为未删除。
- 迁移后用 SQLite 对 v6 样例库执行，与 `schemas/7.json` 逐列比对通过。

## 2. 提醒规则

`reminder_rules` 对 `taskId` 有唯一索引。两台设备给同一个任务各建提醒会得到不同 id，
直接 upsert 会撞唯一索引。`ReminderRepositoryImpl.mergeAll` 按两层匹配：

| 情况 | 处理 |
|---|---|
| 同 id | `updatedAt` 较新者覆盖 |
| 不同 id、同 taskId | 保留本地 id，较新者覆盖内容 |
| 都没有 | 插入；同一批里相同 taskId 只保留第一条 |

`TaskUseCase.save` 在写提醒时统一打 `updatedAt = now`。

## 3. 愿望清单

`wish_items` 增加 `updatedAt`：

- 新增 / 勾选 / 删除都会更新时间戳；
- `mergeAll` 按 id 取较新者，完成状态与删除墓碑都会传播；
- 旧快照的 `updatedAt = 0` 不会覆盖本地较新的愿望。

## 4. 子任务墓碑

- `subtasks` 增加 `deletedAt`；删除改为 `UPDATE deletedAt = :at, updatedAt = MAX(...)`；
- UI 查询（`observeForParent` / `forParent` / `observeAll`）统一过滤 `deletedAt IS NULL`；
- 同步 / 备份使用的 `all()` 仍包含墓碑，删除可以跨设备传播；
- 任务删除时，子任务一并写墓碑。

## 5. 首页主线程

`TodoViewModel.ui` 的卡片聚合加 `flowOn(Dispatchers.Default)`：
任务 / 专注 / 打卡的 filter 和 week 7 天汇总不再占用主线程。与 `StatsViewModel` 一致。

## 6. 快照 v5

- `SyncSnapshot.schemaVersion = 5`；
- 新 App 仍可导入 v2 / v3 / v4 备份；
- 旧版 App 读到 v5 会提示「版本过新」。

## 7. 已知边界

- 提醒规则删除仍是物理删除，没有墓碑；跨设备删除不会传播（编辑会）。
- 「清除所有数据」会物理删除子任务（这是用户主动清空，不做墓碑保留）。
- 打卡 `count` 仍取 max 而非求和（v1.8.0 的取舍）。
- 同步上传自己的快照仍在合并事务之外；上传失败下次重传，不丢数据。
