# 番茄芽 v1.7.1 维护说明

这一版没有新增用户功能，目标是把 v1.7.0 留下的结构债和数据一致性缺口收掉。

## 1. 专注页拆分

| 文件 | 职责 | 行数 |
|---|---|---|
| `ui/focus/FocusTimerViewModel.kt` | 任务与时长选择、结算弹窗、音频/显示偏好、通知指令转发 | 约 520 |
| `ui/focus/FocusTimerController.kt` | 计时状态、500ms ticker、快照恢复、实时活动、兜底通知 | 约 230 |
| `ui/focus/FocusTimerChrome.kt` | 顶部工具条、底部亮度/音频/控制区 | 约 270 |
| `ui/focus/FocusTimerDialogs.kt` | 记录确认、停止确认、结算摘要三个弹窗 | 约 190 |
| `ui/focus/FocusTimerScreen.kt` | 页面布局与生命周期效果 | 458 |

计时运行时不再依赖 ViewModel：

- 空闲（`timer == null`）时 ticker 挂在 `active.first { it }` 上，**不产生唤醒**；
- 运行/暂停时每 500ms tick，每 2 秒轮询一次通知按钮命令；
- 结算、音频、界面状态仍然只在 ViewModel 里，Controller 不反向依赖 UI。

快照存储从 `ui/focus/FocusTimerStore.kt` 移到 `data/focus/FocusTimerStore.kt`，数据层可以安全地在「清除所有数据」时清掉它。

## 2. 数据一致性

### 2.1 番茄账本重算

新增 `TaskDao.recountCompletedPomos()` / `TaskRepository.recountCompletedPomos()`：

```sql
UPDATE tasks SET completedPomos = (
    SELECT COUNT(*) FROM focus_sessions f
    WHERE f.taskId = tasks.id
      AND f.deletedAt IS NULL
      AND f.mode = 'pomodoro'
      AND COALESCE(f.outcome, 'completed') = 'completed'
)
```

调用点：

| 场景 | 位置 |
|---|---|
| WebDAV 合并完成、推送本地快照前 | `SyncEngine.sync()` |
| JSON 备份导入完成 | `BackupManager.importJson()` |
| 清除所有数据 | `DataResetManager.resetAll()` |

这样多设备各自 +1 后即使按 `updatedAt` 覆盖整行任务，账本也会在下次同步时回到专注记录的真实数量。

### 2.2 冲突副本

`SyncEngine.merge()` 创建「（冲突副本）」时，会一并复制：

- `habitRules` / `goalRules`（新 taskId）
- `reminders`（新 id + 新 taskId）
- `subTasks`（新 id + 新 parentTaskId）

副本不再是「有标题、没有规则」的裸任务。

### 2.3 清除数据

`DataResetManager.resetAll()` 的顺序改为：

1. `reminderScheduler.cancelAll()`（AlarmManager 里已排期的提醒）
2. `FocusTimerStore.clear()`（计时快照）
3. 任务 / 子任务 / 打卡 / 专注 / 愿望软删除，提醒规则物理删除
4. `recountCompletedPomos()`（账本归零）

## 3. 其他

- `StatsViewModel` 的聚合加 `flowOn(Dispatchers.Default)`，避免多年记录在主线程分组；日均只统计有专注的天数。
- `ReminderNotifier` 的通知 id 从 `hash & 0xFF`（256 槽）改为 `hash & 0xFFFF`（65536 槽）。
- 专注恢复顺序改为「设置 → 任务 → 快照」，结算时能拿到任务，自动打卡不再漏。
- `resetTimer()` 恢复旧行为：同时停止白噪音并清空音频状态。
