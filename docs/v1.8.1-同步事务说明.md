# 番茄芽 v1.8.1 · 同步事务与子任务合并

这一版只收数据层尾巴：事务边界、冲突副本幂等、子任务时间戳、同步后徽章评估。

## 1. 事务边界

### 同步

旧流程：

```
merge(远端文件)            // 多次独立写入
upsertManifest(文件)       // 另一个写入
```

任何一步失败，前面的写入已经落地，但 manifest 没更新 → 下次重试会再合并一遍，
冲突副本可能重复生成。

现在：

```kotlin
val report = db.withTransaction {
    val merged = merge(snapshot, lastSync, started)
    syncDao.upsertManifest(...)
    merged
}
```

合并与 manifest 同生共死；失败整体回滚，下次从干净状态重试。

### 导入

`BackupManager.importJson` 把任务、规则、子任务、打卡、专注、徽章、愿望、提醒、
番茄账本重算全部放进一个 `db.withTransaction`。DataStore 设置放在事务之后
（它不是 Room 数据，失败只影响设置，不影响已导入的数据）。

### 清除数据

`DataResetManager.resetAll` 的数据库部分同样是一个事务；取消 Alarm 与清计时快照
在事务外（不是 Room 数据）。

## 2. 冲突副本幂等

旧：

```kotlin
val copyId = UUID.randomUUID().toString()
```

同一次冲突如果因为后续步骤失败而重试，会再生成一份「（冲突副本）」。

现在：

```kotlin
val copyId = "conflict-${r.id}-${r.updatedAt}"
```

- 同一远端版本 → 同一个 id → `restoreAll(overwrite = false)` 直接跳过；
- 远端后来又改了 → `updatedAt` 变化 → 新 id，允许再生成一份新的副本；
- 子任务用 `conflict-sub-<id>-<updatedAt>`，提醒用 `conflict-rem-<id>-<updatedAt>`。

## 3. 子任务双向合并（DB v6）

```sql
ALTER TABLE subtasks ADD COLUMN updatedAt INTEGER NOT NULL DEFAULT 0;
UPDATE subtasks SET updatedAt = createdAt WHERE updatedAt = 0;
```

- `SubTaskEntity` 对应 `@ColumnInfo(defaultValue = "0")`；
- 新增 / 勾选子任务时写入 `updatedAt = now`；
- `SubTaskRepository.mergeAll`：远端 `updatedAt` 更晚才覆盖标题 / 完成状态 / 排序；
- 迁移后用 SQLite 对 v5 样例库执行，与 `schemas/6.json` 逐列比对通过。

**边界**：子任务删除仍是物理删除，没有 tombstone，删除不会跨设备传播；
本版只合并「新增 / 修改」。

## 4. 同步后刷新徽章

`SyncEngine` 与 `BackupManager` 现在注入 `BadgeRefresher`：

- 同步合并完成、番茄账本重算之后，主动 `refresh()` 一次；
- 导入事务提交之后同样刷新一次；
- 远端数据解锁的徽章不再需要等下一次本地打卡。

## 5. 快照 v4

- `SyncSnapshot.schemaVersion = 4`；
- v2 / v3 备份仍可导入（新字段有默认值）；
- 旧版 App 读到 v4 会提示「版本过新」。

## 6. 已知边界

- 子任务物理删除不传播（见上）。
- 打卡 `count` 仍取 `max` 而非求和（v1.8.0 的取舍，避免越界显示）。
- `SyncEngine` 的「上传自己快照」不在合并事务内；上传失败时本地已合并，
  下次同步会重新生成并上传，不会丢数据。
