# 番茄芽 v1.8.3 · 规则与提醒收尾

这一版把「提醒删除」和「习惯 / 目标规则」补成记录级合并，
同时把专注页最后的两个职责从 ViewModel 拆出去。

## 1. 迁移 7 → 8

```sql
ALTER TABLE reminder_rules ADD COLUMN deletedAt INTEGER;

ALTER TABLE habit_rules ADD COLUMN updatedAt INTEGER NOT NULL DEFAULT 0;
UPDATE habit_rules SET updatedAt = 1 WHERE updatedAt = 0;

ALTER TABLE goal_rules ADD COLUMN updatedAt INTEGER NOT NULL DEFAULT 0;
UPDATE goal_rules SET updatedAt = 1 WHERE updatedAt = 0;
```

- `reminder_rules.deletedAt` 可空，旧行全部未删除；
- 规则没有 createdAt，旧行回填 1（视为本地已存在），避免远端旧快照 `updatedAt = 0` 覆盖本地；
- 迁移后用 SQLite 对 v7 样例库执行，与 `schemas/8.json` 逐列比对通过。

## 2. 提醒墓碑

`reminder_rules` 对 `taskId` 有唯一索引。软删除后墓碑仍占着这个键，
如果用户重新开启提醒、又生成一个新 UUID，会直接撞唯一索引。

`ReminderRepository.saveForTask` 因此：

1. 先按 taskId 查 `forTaskAny`（包含墓碑）；
2. 有墓碑 → 复用旧 id，写 `deletedAt = null` 复活；
3. 没有 → 用传入的新 id 插入；
4. 返回实际落库的 `ReminderRule`，`HabitEditViewModel` 用它来排 Alarm。

同步 / 导入的 `mergeAll` 同样按 id + taskId 双键合并；删除墓碑按 `updatedAt` 传播。
`ReminderScheduler` 与 `ReminderReceiver` 都会跳过 `deletedAt != null` 的规则。

## 3. 习惯 / 目标规则时间戳

- `HabitRule` / `GoalRule` 增加 `updatedAt`；
- `TaskUseCase.save` 写规则时统一打 `updatedAt = now`；
- `TaskRepository.mergeHabitRules` / `mergeGoalRules` 按 taskId 取较新者；
- `SyncEngine` 只把规则合并到「未删除且类型匹配」的任务：
  - 任务从 HABIT 改成 TODO → 远端旧 habitRule 不会被复活；
  - 任务已删除 → 规则不落地；
- `BackupManager` 也从「只补缺失」改为按 `updatedAt` 合并。

规则删除仍是物理删除，但类型守卫保证旧规则不会在类型转换 / 删除后复活。

## 5. 快照 v6

- `SyncSnapshot.schemaVersion = 6`；
- 新 App 仍可导入 v2–v5 备份；
- 旧版 App 读到 v6 会提示「版本过新」。

## 6. 已知边界

- 习惯 / 目标规则删除是物理删除；靠类型守卫避免复活，但没有独立墓碑。
- 打卡 `count` 仍取 max 而非求和。
- 同步上传自己的快照仍在合并事务之外；上传失败下次重传，不丢数据。
