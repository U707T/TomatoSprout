# 番茄芽 v1.7.2 性能说明

这一版只做性能与同步正确性，不改交互。

## 1. 统计为什么变快

旧路径（每次统计 / 每次徽章刷新）：

```
StatsCalculator.build
  └─ 每个习惯
       ├─ currentStreak  → 逐天 isMet → filter 全量 CheckIn
       ├─ longestStreak  → 逐天 isMet → filter 全量 CheckIn
       └─ completionRate → 逐天 isMet → filter 全量 CheckIn
  └─ countPerfectDays → 730 天 × 每个习惯 × filter 全量 CheckIn
```

复杂度约 **O(天数 × 习惯 × 打卡记录数)**。两年、5 个习惯、1000 条打卡时，
每次统计是百万级比较；而打卡、专注结算、徽章解锁都会触发统计。

新路径：

```
CheckInLedger(checkIns)         // 一次 O(记录数)
  └─ taskId → date → count      // 查询 O(1)
StatsCalculator.build
  ├─ 每个习惯：逐天查 ledger    // O(天数 × 习惯)
  └─ countPerfectDays：同样    // O(730 × 习惯)
```

同一组数据从百万级比较降到约一万次哈希查找。

`CheckInLedger` 的规则：

- 软删除记录忽略；
- 同任务同一天多条记录按 `max(1, count)` 累加；
- 保留 `latestDate`，兼容跨时区留下的未来日期记录（连续天数不被误判中断）。

## 2. 徽章刷新

`FocusSessionUseCase.settle()` 原来的顺序：

1. `CheckInUseCase.recordFromFocus()` 内部刷新一次徽章（此时 FocusSession 还没落库）；
2. 写完 FocusSession 后再刷新一次。

一次专注跑两遍全量统计，而且第一遍看不到本次专注。v1.7.2 起 `recordFromFocus`
不再刷新，由结算在会话落库后统一刷新一次。

## 3. WebDAV 增量

- `SyncManifestEntity.remoteEtag` 与本次 `PROPFIND` 的 ETag 一致时，直接跳过下载；
- 冲突判定使用「上次同步时间 − 5 分钟」作为变化窗口，容忍设备时钟偏差：
  - 远端与本地都判为变化 → 生成冲突副本（安全）；
  - 只有一端变化 → 接受该端；
  - 都不变 → 跳过。

宁可多一个冲突副本，也不因为时钟慢几秒静默丢掉一端的修改。

## 4. 清理死代码

`CheckInUseCase` 里 v1.0 遗留的 `observeToday()`、`TodayItem`、`TodayData`、`undo()`、
`removeAll()` 与 `FocusRepository` 依赖在 v1.6 之后已无任何调用方，本版一并删除：
270 → 153 行。保留的公开入口只有 `toggleToday`、`recordFromFocus`、`makeup`、
`updateMeta` 和 `streakOf`。
