# v1.12.0 — 澎湃 OS 4：改走「实时更新」上岛

## 一、现象

v1.11.0 之后仍有反馈：**通知栏有实时通知，超级岛没动静。** 也就是说：
通知发出来了、倒计时在走、按钮能点，只是岛不出现。

## 二、参考实现给出的答案

拆了 `Live Clock 2.3.0`（`com.platelet.liveclock`，minSdk 36 / targetSdk 36，在澎湃 OS 4 上能出岛）：

| 检查项 | 结果 |
|---|---|
| 是否用 `miui.focus.param` / `miui.focus.pics` / `miui.focus.actions` | **完全没有**，反编译后搜不到任何 `miui.focus` 字样 |
| 是否用 `Notification.ProgressStyle` | 没有 |
| 是否有自定义 `RemoteViews` | 没有 |
| 是否声明 `com.xiaomi.xms.APP_ID`（小米白名单） | **没有** |
| 通知里到底有什么 | `android.shortCriticalText`（状态栏短文案）+ `android.requestPromotedOngoing=true` |
| 其他 | 前台服务（`specialUse`）+ 频道 IMPORTANCE_LOW，每秒重发一次文本 |

关键代码（smali 还原）：

```java
Notification.Builder b = new Notification.Builder(ctx, channel)
    .setSmallIcon(icon)
    .setContentTitle("当前时间")
    .setContentText(value)
    .setOngoing(true)
    .setOnlyAlertOnce(true)
    .setShowWhen(false)
    .setContentIntent(pi)
    .setCategory("status")
    .setVisibility(VISIBILITY_PUBLIC)
    .setForegroundServiceBehavior(FOREGROUND_SERVICE_IMMEDIATE)
    .addAction(stopAction);
// 关键两行：直接写 extras，不调 36.1 才有的 setter
b.getExtras().putCharSequence("android.shortCriticalText", value);
b.getExtras().putBoolean("android.requestPromotedOngoing", true);
```

**结论：澎湃 OS 4 的超级岛渲染的是 Android 16 的「实时更新 / 提升通知」**，
不是厂商焦点通知通道。后者要过云端白名单，第三方应用基本没戏；前者是平台能力，谁都能用。

这也解释了为什么 v1.11.0 把参数写对了仍然没岛 —— 通道选错了。

## 三、本版改动

| 位置 | 改动 |
|---|---|
| `AndroidManifest.xml` | 新增 `android.permission.POST_PROMOTED_NOTIFICATIONS`（普通权限，无运行时弹窗；官方实时更新的硬性前提） |
| `FocusLiveNotification` | 实时更新档位改为写 `android.shortCriticalText` + `android.requestPromotedOngoing` **两个 extras**（不调 36.1 才有的 `setRequestPromotedOngoing` / `setShortCriticalText`，36.0 的 SystemUI 一样认） |
| 同上的样式 | 去掉 `ProgressStyle`，回到标准样式 —— 官方允许的样式里它最稳，也不会让岛改画进度条 |
| `LiveSurfacePolicy` | **Android 16+ 且允许提升通知 → 实时更新**（澎湃 OS 4 的默认路径）；**OS3 及更早的小米机型 → 焦点通知参数**；强制开关仍然优先 |
| 测试岛 | 走和真实专注**完全一样**的档位（只跟开关走），不再固定强制厂商参数，否则自检通过、真实专注不上岛 |
| 自检 | 新增「提升结果」：`已提升为实时更新` / `未提升（系统只当普通通知）` / `当前没有专注通知`，并给出对应操作 |

档位判定现在是：

```
实时活动关闭 → 普通卡片
强制焦点通知 → 厂商参数（OS3 / 白名单用户）
Android 16+ 且允许提升 → 实时更新（OS4 默认）
小米机型（其余情况）→ 厂商参数兜底
其他 → 普通卡片
```

## 四、必须满足的系统条件

官方对「实时更新」的硬性要求，缺一条就不会被提升（自检会显示「未提升」）：

- 声明 `POST_PROMOTED_NOTIFICATIONS` 权限 ✅
- `setOngoing(true)` ✅
- 有 `contentTitle` ✅
- 没有 `setCustomContentView`（普通卡片档位才有，且那一档不请求提升）✅
- 不是分组摘要、没有 colorized ✅
- 频道不是 `IMPORTANCE_MIN` ✅

用户侧还需要：设置 → 通知 → 番茄芽 → **允许实时更新**（默认开，可被关掉）。

## 五、验证

1. 「我的 → 提醒 → 系统实时活动」，确认「本次走：Android 16 实时更新」。
2. 点「发送测试岛」：状态栏出现胶囊，展开是系统的实时更新卡片，岛上出现番茄图标与倒计时。
3. 回到自检面板再看一次：**提升结果应为「已提升为实时更新」**；若为「未提升」，按提示去开系统开关。
4. 开一轮真实专注：暂停 / 继续 / 结束 / 延长 5 分钟都应生效（通知按钮走广播）。

命令侧：

```bash
adb shell dumpsys notification --noredact | grep -E "FLAG_PROMOTED|shortCriticalText|requestPromotedOngoing"
adb shell cmd notification get_promoted  # 部分 ROM 支持
```

## 六、限制

- 「实时更新」是 Android 16 的平台能力，**澎湃 OS 4 是否把它画成岛由 ROM 决定**；本版按官方通道发送，系统不画就是普通通知，计时与结算不受影响。
- OS3 及更早的机型仍然走厂商 `miui.focus.*`，那条路要过白名单（见 `docs/v1.11.0-澎湃OS4超级岛.md`）。
- 本版**没有**引入前台服务：参考实现用 FGS 是为了每秒重发文本，我们的秒数由 `timerInfo` / chronometer 交给系统走，不需要常驻服务。
- 频道仍是 `IMPORTANCE_HIGH`（要求只是「不是 MIN」）；如果你在系统里把该频道压到最低，实时更新会失效。
